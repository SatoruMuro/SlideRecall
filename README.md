# SlideRecall

発表スライドを見ながら話す内容を思い出し、原稿との答え合わせと自己評価を繰り返す、日本語の練習用PWAです。PDF・原稿・練習履歴は、このブラウザのIndexedDBに保存します。ユーザー登録、クラウド同期、音声録音、AI採点はありません。

初めて使う方は「発表を取り込む」と「練習する」を読み、使い続ける前に「バックアップと保存の注意」を確認してください。開発・公開の手順は後半にまとめています。

## 発表を取り込む

1. 「新しい発表を追加」でPDFを選び、発表タイトルを入力します。
2. `.txt` / `.md` の原稿を選ぶか、原稿欄に貼り付けます。下のようにスライド番号を見出しにしてください。
3. 対応表でPDFページと原稿を確認してから保存します。欠番は空欄のまま保持します。番号の重複やPDFページ数との違いは警告されるので、対応を確認してください。

```text
Slide 1:
最初のスライドで話す内容。
本文の改行も保持されます。

Slide 2：
次のスライドで話す内容。

スライド 3:
結論。
```

`Slide` は大文字・小文字のどちらでも使えます。半角・全角のコロンに対応しています。PDFだけ、原稿だけでも保存できます。PDFに対応しない原稿のページは、PDFのないスライドとして扱います。重複番号の本文は元の順番でまとめられるため、保存前に内容を確認してください。

「原稿を編集」では、原稿全文、冒頭・締めのアンカー、必須の説明ポイント、次のスライドへの接続、目標時間を編集できます。アンカーは正確に再現したい言葉、説明ポイントは意味を伝えたい内容です。編集は自動保存され、変更後の原稿には新しい改訂番号が付きます。保存失敗の表示が出た場合は画面を閉じず、内容を手元に控えてください。

## 練習する

| モード | 使い方 |
| --- | --- |
| 順番練習 | 全体または指定範囲を順に練習する |
| 苦手集中 | 現在の改訂の評価とヒント利用から復習対象を優先する |
| ランダム練習 | 指定範囲を重複なしで並べ替えて始める |
| 本番リハーサル | 最後まで続けて発表し、終了後にまとめて自己評価する |

練習開始時は原稿を隠します。必要な場合はキーワード、冒頭アンカー、全文の順にヒントを開けます。「発話を終えて答え合わせ」で開く全文はヒント利用に数えません。自己評価は「◎ スムーズ」「△ あいまい」「× 再現困難」の3段階です。◎は原則として、ヒントなしで必須内容と指定アンカーを再現できた場合に選びます。判定はユーザー自身によるもので、機械による正誤判定ではありません。

×は数枚後、△は終盤に再出題します。同じスライドの出題回数には上限があります。途中でやめる場合も「保存して終了」を使えます。リハーサルではスライド別・合計の発話時間を記録し、未評価の記録は結果画面で評価できます。

キーボードでは `H` でヒント、`Space` で一時停止・再開、左右矢印で移動、`1` / `2` / `3` で自己評価を操作します。入力欄の編集中はショートカットを無効にします。ボタンでも同じ操作ができます。全画面APIが使えない環境では、画面内を広く使う表示に切り替えます。

## バックアップと保存の注意

「設定・バックアップ」でPDF・原稿・履歴をまとめてZIPに保存できます。復元時は新しいIDを割り当てるため、既存の発表を上書きしません。ZIP内の形式・バージョン・関連ID・ファイル数・展開後サイズを検証し、不正なバックアップは拒否します。削除には確認が必要です。

**ZIPは暗号化されていません。** 保存先と共有相手に注意してください。ローカル保存も暗号化を意味しません。

ブラウザのサイトデータ削除、プライベートブラウズ終了、端末の空き容量不足などで保存内容を失うことがあります。保存容量の表示や保持申請は、対応ブラウザで利用できますが、データ保持を保証しません。端末・ブラウザ・ホーム画面に追加したPWAの間では自動同期しません。定期的にZIPを保存してください。

## オフラインで使う

初回はオンラインで開き、アプリの静的ファイルのキャッシュを完了させてください。その後はオフラインで起動し、保存済みPDFの表示、原稿編集、練習、保存、ZIPバックアップを使えます。Service WorkerがキャッシュするのはアプリのHTML・CSS・JavaScript・アイコンなどです。取り込んだPDF・原稿・履歴はCache Storageに保存しません。

更新が見つかると通知します。作業を保存してから更新ボタンを押してください。通常の画面遷移にサーバー側ルーティングは使わず、GitHub Pagesの `/SlideRecall/` の下で動作します。

## データを外部送信しない設計と、その範囲

PDFはファイルまたは保存済みBlobからバイト列を読み、ローカルに同梱したPDF.js workerで描画します。PDFのリンクは開かず、原稿のMarkdownはHTML化せずにプレーンテキストとして表示します。アップロードAPI、アクセス解析、外部フォント、CDN、リモートWorker、例外転送は実装していません。公開用の `dist/` にはアプリの静的ファイルだけを入れます。

本番ビルドのE2Eテストでは、合成PDFと識別用トークンを含む架空の原稿を取り込み、編集・練習・保存・バックアップ時のHTTPリクエストを記録します。同じオリジンにあるアプリのGET以外の通信、トークンのURL・ヘッダー・本文への混入、アセットの404を検査します。テストデータに実際の発表資料は使いません。これらの確認はテストした環境と操作についての検証であり、端末全体の安全を保証するものではありません。

GitHub Pagesでは任意のレスポンスヘッダーを通常設定できないため、CSPはHTMLの `meta` 要素で指定しています。CSPはスクリプトや接続先を制限する補助策です。`frame-ancestors` やレポート専用ポリシーなど、metaでは使えない機能があり、CSPだけで安全を保証しません。

`https://satorumuro.github.io` の別サイトは同一オリジンです。別リポジトリのサイトでも、同じオリジンのIndexedDBにアクセスできる可能性があります。DB名の分離はセキュリティ隔離ではありません。機密性が高い用途では、このアプリだけに使う独立したカスタムサブドメインを検討してください。移行しても既存データは自動で移らないため、ZIPで移します。

Pagesサイトへのアクセスや静的ファイルの取得については、GitHub側にアクセスログ等が残り得ます。アプリは取り込んだPDFや原稿をその通信に載せません。ブラウザ拡張、端末のバックアップ・同期、不正アクセスに対する防御は、このアプリの範囲外です。

## 開発とテスト

Node.js 24 LTSとnpmを使います。

```sh
npm ci
npm run dev
```

変更後の確認:

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwrightは本番ビルドを `http://127.0.0.1:4173/SlideRecall/` で配信して検査します。E2Eで使う3ページのPDFはテスト実行時に生成します。通信を観測するためService Workerを有効にし、オフライン起動・PDF描画・編集内容の永続化と、空の別ブラウザへのZIP復元も確認します。テスト用ZIPは `test-results/` に出力され、公開成果物には含めません。

主な構成:

| 場所 | 内容 |
| --- | --- |
| `src/domain/` | 発表・スライド・練習記録の型 |
| `src/features/` | 取り込み、編集、練習、統計、設定 |
| `src/lib/storage/` | IndexedDBとスキーマ移行 |
| `src/lib/backup/` | ZIPの作成・検証・復元 |
| `src/lib/pdf/` | PDF.jsの設定と読み込み |
| `tests/e2e/` | 合成データによるブラウザテスト |
| `.github/workflows/deploy.yml` | 検証とGitHub Pages公開 |

実行結果は各コミットのGitHub Actionsで確認してください。iPhone実機・iOS Safari・ホーム画面に追加したPWAの保存挙動は未検証です。デスクトップの自動テストだけで実機確認済みとは扱いません。

2026-10-28時点の `npm audit` では、本番依存の報告は0件、開発依存は `deepmerge` / `workbox-build` 経由でLowが4件でした。古いメジャーバージョンへの強制変更は行っていません。依存の監査結果は時間とともに変わるため、更新時に再確認してください。

## GitHub Pagesへ公開する

リポジトリの `Settings → Pages → Build and deployment → Source` を **GitHub Actions** に設定します。`main` へのpush、またはActionsの手動実行で、lint・型検査・単体テスト・ビルド・Chromium E2Eを実行し、成功した `dist/` だけを公開します。Pull Requestでは検証のみを行います。公開先の環境は `github-pages` です。

公開先は `https://satorumuro.github.io/SlideRecall/` を想定した設定です。公開の完了はActionsのdeployジョブと実際のURLで確認してください。設定や権限が不足している場合、検証が通っていても公開には失敗します。Pagesサイトは原則公開されるため、認証済みユーザー専用サイトとしては扱えません。

Actionsの権限は、検証に `contents: read`、公開ジョブに `pages: write` と `id-token: write` を指定しています。公開同士の衝突はconcurrencyで防ぎ、ユーザーデータや開発用の秘密情報を成果物に含めません。

設定の根拠: [ViteのGitHub Pages配信ガイド](https://vite.dev/guide/static-deploy#github-pages)、[GitHub Pagesの公開ソース設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。不具合は、機密資料や原稿を添付せず、再現手順を[Issues](https://github.com/SatoruMuro/SlideRecall/issues)に記載してください。
